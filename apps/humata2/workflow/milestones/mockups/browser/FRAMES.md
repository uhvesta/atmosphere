# Frames: agents use my own browser, asking me first

HTML mockups, not renders of the app. They are laid out at 1280x760, the size of the app's design frames, and shot at 1.25x, so each PNG is 1600x950. Sources are in `src/` (`sh src/shoot.sh` rebuilds and screenshots all three). The sidebar and Settings copy the approved design frame 29; the request cards copy frames 201 to 204 and the card the app builds today (`ui/workspace/src/request_card.rs`, the wide decision card).

- `b1-settings-browser.png`: I open Settings > Browser. I see which agents may use my browser, then a table of the browsers found on this Mac with two columns of state, Host and Extension, and the buttons that fix each row: Chrome is set up and connected (Uninstall), Brave is set up but not connected and says to load the extension, Edge's host is out of date and says why Edge can't connect (Update host, Uninstall), Firefox is not set up (Set up host). "Install all" sits above the table. Under it, how to load the extension in each browser family with the folder to pick, and the two things I am asked. Shows: Browser is the sixth row of the Settings list, after Agent access; a row only carries a second line when something blocks it and that line says what to do.
- `b2-inbox-browser-read.png`: Claude Code on devbox-1 asks to read a tab. I see the card name the agent and its machine in the title and in From, the tab's title and URL, the browser, what is read, the agent's reason, and what Humata worked out: nothing is clicked, the page is read signed in as me, and Allow 30 min lets this one session read any tab and list my tabs until the time shown, or until Humata restarts (D897). Shows: exactly three buttons, Allow once, Allow 30 min and Deny; no Ask why, no Always allow box, no rule link.
- `b3-inbox-browser-write.png`: Claude Code on devbox-1 asks to click "Merge pull request". I see the URL in an amber box, the target as the text I would see on the page with its kind and selector under it, and the warnings that the click is made as me and that Humata can't tell what the page does next. Shows: dark mode; exactly two buttons, Allow once and Deny; the foot of the card says it is asked every time and, because Allow all is on screen, "Not part of Allow all"; with two requests waiting the button reads "Allow all 1".

The effect rows ("What else it affects") and the "Can it be undone?" line are written by the daemon, not by the app; the frames show fixture text. Each line must be true of what the extension does. "If the target is no longer on the page, nothing is clicked" in b3 is not yet checked against the extension: back it there or drop the row.

b3's "Allow all 1" and "Deny all" stay: the UI lane builds them, and the count leaves browser writes out.

Signed off by the design judge, 2026-11-20: all three frames; b2 re-signed after the 30-minute grant became per session (D897). UI lanes copy them exactly.
