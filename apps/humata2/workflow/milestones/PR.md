### Design notes
- **Daemon:** new `daemon/humatad/src/review/pull_requests.rs` (+ `pull_requests/{resolve,start,heads,submit}.rs`) serves PullRequestReviewService. `gh` runs on the host with the host's own login (`gh_program()` moved to a shared `gh.rs` seam so push and PR share it); no token is read, stored or sent. Resolve uses `gh pr view --json`; Submit uses `gh api repos/{o}/{r}/pulls/{n}/reviews --input -`; heads use `gh pr view --json headRefOid,state` plus `git fetch` of `refs/pull/<n>/head`.
- **Review session:** StartReview makes the PR reviews channel on first use (repos added as PRs come), starts one session through the existing start path with each PR's head branch name (FC-18, PR-6), clones under `~/Humata/pr-reviews/sessions/<review>/<repo>`, records the binding (PRs, push allowed) on the session, and types the review chat's first message (PR URLs, titles, base/head, the user's context, the PR-23 tools; it is told to wait and never to review). Identity maps a bound session to `SessionKind::Review { push_allowed }`.
- **Drafts:** the PR destination joins the one comment model (pick 2 below): a PR draft is a Comment with destination `pull_request`, author user or agent, statuses draft → posted (with `posted_url`), and `outdated` when its lines change (PR-16, the same placement as notes). Make it a draft is one review-chat change with Undo.
- **Submit (PR-12–PR-14):** PlanSubmit lists drafts per PR, the agent's summary (DraftSummary / `review_summary_draft`), and a single-use plan token; SubmitReview posts one review per PR, write-ahead per PR so a restart never posts twice blindly (pick 6), and a partial failure says which PRs posted and keeps the rest as drafts.
- **New commits (PR-15–PR-17):** the daemon checks each review's heads (pick 5: 1 min while the app reports it open, else 5 min; one batched graphql query per tick) and puts a head change on the event feed; Update the clone fetches, reports a force-push, marks drafts and notes on changed lines outdated, and types the agent the new commits and changed files. Merged or closed shows Archive; the archive dialog names unsubmitted drafts.
- **Diff base (PR-10):** each repo's base is the PR's base. VIEWS owns the per-repo diff spec (RV-31) and `review_prepare` (RV-32–RV-34); PR only sets each repo's spec at start through VIEWS's API. Until it lands, PR uses today's `DiffBase` per session and logs the gap.
- **App (TCA split):** new feature crate `features/pr_review` (dialog, submit, heads notice, chat follower; pick 9) so PR stays out of VIEWS's `features/review/src/lib.rs`. Clients: new `clients/src/pull_requests.rs` and `clients/src/review_chat.rs` traits with scripted fakes and live clients with parity tests; the comments model gains destination and agent author. The chat follower applies agent view changes only once the user is quiet (pick 8), with Undo per change and Back.
- **UI:** frame 67 (dialog over Home, from ⌘K or the PR reviews channel), 68 (session: Submit review in the header, Draft for GitHub cards by author with Edit/Drop, "PR #482 against main · 2 repos", per-repo `#n`, Drafts footer, new-commits notice at the foot of the chat), 69 (Submit review: drafts per PR, verdict per PR, the agent's summary, "Posts one review per PR with This Mac's gh"). PR-specific drawing in new `ui/src/{overlay_pr_review,overlay_submit_review,panel_changes_pr,review_chat_strip}.rs`; `panel_changes.rs`, `panel_info.rs`, `shell.rs`, `ui/src/lib.rs` get call lines as seams.
- **New frames (proposed, owner sign-off via main):** PR-17 merged notice with Archive; PR-18 PR reviews channel Sessions table; PR-25/PR-8 Info panel switches; PR-13 partial failure; where the per-change Undo sits (pick 1). Numbered 72+ by main. Advisor (pick 10): only the Undo strip needs a frame, as a golden 68 redraw; the rest follow existing patterns.
