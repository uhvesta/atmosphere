- Design notes:
  - New package `clients/live` (`humata2_clients_live`, visible to `desktop` and its own tests). `LiveDaemon` implements the existing `Daemon` and `Terminals` traits over the host socket with humatad's generated tonic clients (`//apps/humata2/daemon/humatad:grpc`). It covers what This Mac's daemon serves today: `load` (GetServerInfo + ListChannels + ListSessions, mapped to `model`), `events` (EventService.Subscribe for sessions, channels, machines; Resync; plus `TerminalData` from its attaches), `create_channel` (CreateChannel, waits for the setup operation), `create_session` (StartSession with the options' repos and first message), `resume` (ResumeSession), `send` (TerminalService.Type), and `Terminals` (ListTabs/OpenShellTab, one Attach per open tab: input, resize, output as `Event::TerminalData`). Every other call answers `DaemonError::Refused` saying it comes in a later release. Agents map by name through `LiveOptions` (tests map Claude to the test agent). Its own connect errors are a thiserror enum with sources; trait methods map to `DaemonError` (Clone, no sources) with actionable text.
  - Parity suite `clients/live/tests/parity.rs`: each case is a function over `(Arc<dyn Daemon>, Arc<dyn Terminals>)` and a small `World` trait (make a repo, the This Mac id); run once on `FakeDaemon` and once on `LiveDaemon` against `humatad2_admin` with file remotes and the test agent (the humatad tests' World, copied small). Its rust_test needs humatad2_admin and the holder as data: a test-only filegroup in `daemon/humatad/BUILD.bazel` re-exports the holder, so `daemon/holder/BUILD.bazel` stays untouched.
  - New package `desktop/install` (`humata2_install`, visible to `desktop`): TS-0 / D51 / PER-20: copy the bundled `humatad2`, `humata2_holder`, `humata` into `~/.humata2/bin` by checksum with an atomic swap, write and load the launchd agent (`launchctl` behind a trait), and symlink `humata` into `~/.local/bin`. Behavioural tests in temp folders with a fake launchctl.
  - Later batches: desktop picks the live client and runs the installer on launch (`desktop/src/main.rs`, seam lines in `desktop/BUILD.bazel` for the main agent); the app credential for the release daemon (BOUNDARIES §2.1); session and channel events published by humatad (files held by ASK); headless flows §26.2 and §26.8 in `desktop/tests/` against a real daemon; "Couldn't resume" and New channel progress UI once LOOK1 is committed; app bundle and release script.
