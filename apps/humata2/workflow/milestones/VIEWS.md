### What already exists (read before planning anything new)
- **Daemon, per repo already:** `review.proto` has `DiffSpec`/`RepoDiffSpec` and `DiffBase.spec`; `daemon/review_diff/src/{spec,wire}.rs` computes a diff per repo spec; `review_prepare` and `view_prepare` are MCP tools; a review plan outside the open review chat becomes a draft view (`daemon/humatad/src/review/views.rs`); drafts, MarkReady, SetViewState, ListViews, the event feed (D87, D89) and `humata views|view` (D97) are built.
- **Daemon gaps found:** `get_file_diff` with a multi-repo `DiffBase.spec` takes `spec.repos.first()`, not the file's repo's spec (`daemon/humatad/src/review.rs` ~l.484), so per-repo bases would show the wrong hunks. A spec that leaves out a session repo silently drops it. No RPC lists a repo's branches for a picker. `PushChoice` has no base branch. ViewService isn't relayed and views live on the session's own daemon, so a remote session's views never reach the app (VW-12; D112 keeps views on the host).
- **App gaps:** the app's `clients::model::DiffBase` is one session-wide enum; `features/review` keeps one base per session; `ui/src/panel_changes.rs` draws one "against main ▾". `diff/` (`humata2_diff_view`) has a per-repo `DiffSpec` but the app doesn't use that crate. App views (`features/views`) are fakes only, keyed by title, with no client for ViewService; no Revert snapshot (VW-9), no Keep, no review tab content (VW-6), Journal states are not the VW-10 set.

### Design notes (picks P1–P10 signed off by the Opus 5.5 high advisor, 2026-11-16, with its changes folded in)
- **P1 client diff-spec model:** `clients::model` gets `RepoDiffSpec` (mirrors the proto) and `DiffBase::Spec`. Review state per session is one serializable `DiffTargets` value: the session-wide preset plus per-repo overrides. With any override the client sends a Spec listing every repo it knows, each preset translated exactly as the daemon's constructors in `daemon/review_diff/src/spec.rs` do (`since_branch`, `uncommitted`, `since_last_review`, `since_fork`, all `Compare::everything()`: OriginMain is merge base + unstaged + untracked). "Comparing per repo" shows when the repos' translated specs differ, not merely when an override exists. OtherSession stays session-wide: picking it clears overrides and the per-repo pickers show it read-only. The header picker sets every repo and clears overrides.
- **P2 daemon:** a repo a Spec leaves out gets the OriginMain preset's base through one shared function; `get_diff` cuts the Spec down to `request.repos` when set; a Spec naming a repo outside the session, or one repo twice, is refused with a fix; `get_file_diff` looks up the spec by `wire::repo_key(&repo)` (today `spec.repos.first()`, review.rs ~l.484).
- **P3 picker contents:** presets, then the repo's remote branches from a new `DiffService.ListBases(session, repo)`, then "Branch or commit…". ListBases reads `refs/remotes/origin/*` from the clone without fetching ("as of last fetch"), default branch from `origin/HEAD` (reuse `session_service/pointers.rs` ~l.344) first, then the session's upstream. DiffService is relayed whole, so remote sessions get it free. A typed rev that doesn't resolve fails in GetDiff with a fix; ListBases validates nothing.
- **P4 where the pick lives:** one `DiffTargets` value per session, saved with the app's state in `ReviewSaved` so it survives restarts (main, 2026-11-16, D289(f): persistence is core; task D5). Moving it to a ViewStateService key `diff/<session>/bases` (D34) later is one key.
- **P5 Push & PR per repo:** totals from that repo's diff. `PushChoice.base_branch` becomes `gh pr create --base X` (X without `origin/`, checked to exist on origin; `session_service/push.rs` ~l.454 passes no `--base` today). A PR already open against another base is not retargeted; the plan says "PR #N targets main". `PlanPushRequest` gets an optional `DiffSpec` so the push dialog's +/− equals the repo group's. Unset fields keep today's behaviour.
- **P6 VW-12:** the host keeps offered views. Drafts stay on the machine (and move with the session through SessionCarryService). MarkReady journals a `view.offered` entry with the whole PreparedView on the machine uplink (D225/D226): `JournalEntry` gets a view payload; the host applier gets a `view.offered` arm (D226 pick 5 rejects all but the three inbox operations today), checks the session is one the host places on that machine, upserts idempotently by `vw_` id, and publishes the Updated event (D89). From then on the host owns its state. The agent's ListViews on the machine shows offered views as of MarkReady.
- **P7 app views:** keyed by ViewId; a `ViewsClient` trait (fake + live ViewService); offers, Later and Journal entries arrive on the event feed (push, never poll); every user answer is a SetViewState with an idempotency key. The VW-9 snapshot (route, terminal tab, panel, full screen, board scope, `DiffTargets` and the base-menu state) lives in a new `features/app/src/views.rs`. Revert never touches comments; Keep leaves the view's targets in place.
- **P8 RV-32:** a review_plan view opens the Diff panel with its spec as per-repo targets plus its order (groups and notes too if drawn; otherwise they go on the gap list and the view still opens). A repo in the spec no longer in the session shows as "not in this session". A walkthrough opens the review tab (frame 70).
- **P9/P10:** the PR split and the frames below.
- **Also from the advisor:** the OriginMain preset hard-codes origin/main (`wire.rs` ~l.255): resolve `origin/HEAD`, fall back to origin/main (B5). Reviewed snapshots must be per repo under mixed bases (B6). PlanPush and PushAndOpenPullRequests are not on the SessionService relay list: check how Push reaches a remote session before F2 promises it (F3). Old clients/daemons: force-upgrade rule (VIP "Migrate" message), no fallbacks.
- TCA split kept: state and reducers in `features/{review,views,app}`, views in `ui/`, `ViewsClient` and diff calls behind traits in `clients/` with fakes, live in `clients/live` with parity tests.
